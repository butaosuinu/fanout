並走時の注意

  • rebase 前提ペア(並走できるが、先にマージされた側へ他方が rebase する): #655 ↔ #676(同一パッケージの別ファイル。server.go の lifecycle 部で軽く交差)/ #664 ↔ #682(どちらも web/src。#682 は app 層、#664 は features 側)/ #680 ↔ #681(どちらも web/src。#680 は transport、#681 は features/app)/ #658 ↔ #680(どちらも Makefile にターゲット追加)/ #667 ↔ #683(どちらも DiffOverlay の開閉まわり)。
  • class H に触れる PR は人間レビュー必須。#655 / #657 / #676 / #668 に加え、#678(requireToken の 403)・#663(reviewstore 新設)・#666(main.go dispatch)・#670(briefing)・#680(peek/plan/diff の rename)も H 面に触れる。Makefile / web/package.json / CI workflow を触る #658 / #677 / #682 / #315 / #319 も reviewrisk 上は H 判定。この列挙は例示で、正は PR ごとの reviewrisk(make review-risk)。
  • wave の起動は親 epic ごとに /fanout #親 --unblocked-only を 1 回ずつ(2 epic にまたがる wave 1〜4 は 2 回)。epic 内の blocked-by が wave 内の起動対象を絞る。
  • #628 本文の wave 記載(wave 3 = #668 + #669)は #669 の blocked-by(#668 完了が条件)と両立しないため、本ロードマップは #668 を単独 wave に置いた。wave 6〜8 は本書が正。
